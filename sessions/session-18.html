Overfitting, Generalization and Model Evaluation

A model is only useful if it works on data it has never seen. This session covers why models overfit, the bias–variance tradeoff behind it, the techniques that prevent it, and how holdout evaluation and cross-validation measure generalization.

What overfitting is

Learning the noise instead of the pattern

Overfitting When a model learns the training data too well, including its noise and random fluctuations, instead of the underlying pattern. It performs extremely well on training data but poorly on unseen test data. In short: overfitting = high training accuracy + low test accuracy.

Imagine fitting a curve to 10 data points. A straight line underfits: it's too simple to follow the pattern. A high-degree polynomial overfits: it bends to pass through every point, noise and all. The best model captures the true pattern, not the noise. The model has memorized the data instead of generalizing from it.

Model typeDescriptionError behavior
UnderfittingToo simple: misses important patternsHigh training and test error
Good fitBalanced complexity: captures the trendLow test error
OverfittingToo complex: fits the noiseLow training error, high test error

Causes of overfitting

Too complex a model

Deep networks or high-degree polynomials with room to memorize.

Too few training samples

Not enough data to represent the true distribution.

Noisy data

Outliers or irrelevant features for the model to latch onto.

Too many features

The model finds random relationships that don't hold up.

Insufficient regularization

No constraint on how flexible the model can be.

Data leakage

Information from the test set accidentally used in training.

Spotting it

The symptoms: high training accuracy but low test accuracy, large variation in cross-validation scores, and training and validation error curves that diverge. Training error keeps falling, while validation error falls at first and then rises; the turning point is where overfitting begins.

The bias–variance tradeoff

Why there's a sweet spot of model complexity

Suppose the data follows y = f(x) + ε, where f is the true pattern and ε is random noise. A model estimates f with f̂. Two kinds of error can creep in:

Underfitting → high bias

f̂(x) is systematically different from f(x): the model is too rigid to capture the pattern, whatever data it sees.

Overfitting → high variance

f̂(x) fits f(x) + ε, the noise included, so it changes a lot from one training sample to the next.

Expected test error = Bias² + Variance + Irreducible error

The irreducible error comes from the noise ε itself; no model can remove it. The goal is the complexity that minimizes the sum.

Avoiding overfitting

Eight families of techniques

A. Data-related

Evaluate on unseen data with a train–test split or k-fold cross-validation. Get more data, which smooths out noise, or augment it by creating modified copies (flipped images, reworded text).

B. Model simplification

Use fewer parameters or simpler algorithms, remove irrelevant or redundant features, or reduce dimensions with PCA or LDA.

C. Regularization

Add a penalty for large weights to the loss the model minimizes, so it can't bend freely to fit noise.

D. Early stopping

Watch validation loss during training and stop when it starts to rise, before overfitting sets in.

E. Dropout

In neural networks, randomly switch off neurons during training so they can't co-adapt; this acts as a regularizer.

F. Ensembles

Bagging (random forests), boosting (XGBoost, AdaBoost) and stacking combine models whose different errors average out, reducing variance.

G. Pruning

Cut decision tree branches that add little predictive power, so deep trees can't memorize the data.

H. Cross-validated tuning

Choose hyperparameters (tree depth, α, λ) by cross-validation so they generalize beyond the training set.

Real-world examples

Best practices: use cross-validation for reliable estimates, apply L1/L2 regularization, prefer simpler models when possible, monitor validation loss and stop early, prune trees and reduce dimensions, use ensembles, and gather or augment data. Overfitting isn't about poor training performance; it's about poor generalization. The model must learn the signal, not the noise.

Generalization

The true test of a model

Generalization A model's ability to perform well on unseen data, not just on the data it was trained on. A model generalizes well if it captures the underlying patterns in the data rather than the specific training examples.

Good generalization

Learns the trends, so it performs well on test data.

Poor generalization

Memorizes the noise, so it performs poorly on new data (overfitting).

Example: a model with 98% accuracy on its training set but 68% on the test set generalizes poorly. The 30-point generalization gap is the warning sign.

Generalization matters because it's what makes predictions reliable in real-world conditions: it prevents overfitting, makes models robust and stable, and gives a true estimate of performance. To check it, we must evaluate on data not used in training, using one of two main approaches: holdout evaluation or cross-validation.

Holdout evaluation

One split, set aside once

The holdout method divides the data into two or three separate subsets: a training set for fitting the model, a validation set for tuning hyperparameters, and a test set for the final performance estimate.

SubsetCommon shareExample with 1,000 samplesExample accuracy
Training70–80%70095%
Validation10–15%15088%
Test10–15%15087%

In this example the drop from training to test is small, so the model generalizes well.

  1. Split

    Divide the data into training, validation and test sets.

  2. Train

    Fit the model on the training data.

  3. Tune

    Adjust hyperparameters using the validation data.

  4. Evaluate

    Measure final performance once on the test data.

Advantages

Simple and fast, easy to implement, and works well on large datasets.

Limitations

The result depends on the particular split and can vary with each random partition; it wastes data when the dataset is small; the estimate is less stable.

Cross-validation

Every sample gets a turn in the test set

Cross-validation (CV) Improves reliability by using all the data for both training and testing, in different folds. The data is split into k parts; the model is trained on k − 1 folds and tested on the remaining one, and this repeats k times so each fold is the test set once. The k results are averaged.

VariantDescription
Stratified k-foldKeeps the same class proportions in every fold (for classification)
Leave-one-out (LOOCV)Each sample is the test set once (k = n)
Repeated k-foldRepeats cross-validation with different random splits

Advantages

Uses data efficiently (every sample is used for training and testing), gives more stable estimates, and suits small datasets.

Limitations

More computation (the model is trained k times), slower on large datasets, and folds must keep the same distribution.

Simulation

AspectHoldoutCross-validation
Data used for testingOne portionAll data, once each
StabilityHigh variance (depends on one split)Low variance (averaged over folds)
ComputationFastSlower (k training rounds)
Best forLarge datasetsSmall to medium datasets, comparing models
ResultA single estimateAn average of several estimates, plus their spread

Practical example: a house price model with 10,000 samples. An 80/20 holdout gives a test RMSE of 10.5. Five-fold cross-validation gives an average RMSE of 10.3 with a standard deviation of 0.2 across folds: consistent performance, and a more reliable estimate.

Combining both methods

  1. Set aside a final test set

    Lock it away before any modelling.

  2. Cross-validate on the rest

    Use 5-fold CV on the training data to tune hyperparameters and choose a model.

  3. Test once

    Evaluate the final model on the holdout test set for an unbiased generalization score.

Session 18 in summary

  • Overfitting means high training accuracy but low test accuracy: the model learned the noise, not the pattern.
  • Expected error = bias² + variance + irreducible error; simple models have high bias, complex ones high variance.
  • Prevent overfitting with more data, simpler models, regularization, early stopping, dropout, ensembles, pruning and cross-validated tuning.
  • Generalization is performance on unseen data; watch the gap between training and test scores.
  • Holdout is simple but depends on one split; cross-validation averages over k folds for a stabler estimate. In practice, tune with CV and report on a final holdout test set.
